## 2024-05-24 - Faster Tensor Packing with jnp.pad
**Learning:** When packing multiple tensors together where some channels need to be padded with zeros (e.g. for hardware alignment mod-8), using `jnp.stack` with multiple `jnp.zeros_like()` calls forces JAX to allocate large explicitly zeroed arrays. Using `jnp.stack` only on active variables and then padding the last dimension with `jnp.pad(active, ((0, 0), ..., (0, N)))` bypasses these allocations and translates to much faster slice-update ops in XLA (up to ~1.8x faster on CPU during JIT).
**Action:** When creating mod-N padded tensor structures for kernels, always prefer `jnp.pad` over explicit `jnp.zeros_like` stacking.
## 2025-05-01 - 75x Faster Sequence Filtering with str.translate
**Learning:** In string-heavy processing loops (like protein sequence gap filtering), python generator expressions combined with set lookup (`"".join(c for c in s if c not in set)`) are exceptionally slow. Python's built-in `str.translate` using a pre-computed C-level `str.maketrans` translation table completely avoids Python byte-code evaluation in the loop, yielding ~75x speedups.
**Action:** Always prefer `str.translate()` with pre-instantiated translation tables or vectorized numpy indexing over generator-based character filtering when processing sequences or synthetic data. Avoid redundant set/table instantiations within inner loops.
