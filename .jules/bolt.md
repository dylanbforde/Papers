## 2024-05-24 - Faster Tensor Packing with jnp.pad
**Learning:** When packing multiple tensors together where some channels need to be padded with zeros (e.g. for hardware alignment mod-8), using `jnp.stack` with multiple `jnp.zeros_like()` calls forces JAX to allocate large explicitly zeroed arrays. Using `jnp.stack` only on active variables and then padding the last dimension with `jnp.pad(active, ((0, 0), ..., (0, N)))` bypasses these allocations and translates to much faster slice-update ops in XLA (up to ~1.8x faster on CPU during JIT).
**Action:** When creating mod-N padded tensor structures for kernels, always prefer `jnp.pad` over explicit `jnp.zeros_like` stacking.

## 2024-05-25 - Hoisting Loop-Invariant Exponentials Before Broadcasting
**Learning:** In Pallas kernel backward passes (e.g. `dq_kernel_multi`), calculating `jnp.exp()` of potential differences on fully broadcasted 3D tensors (`(BATCH_BLOCK, BLOCK_M, BLOCK_N)`) inside the inner loop is extremely expensive and wastes MUFU resources. Computing the `jnp.exp` on the 2D arrays (`(BATCH_BLOCK, BLOCK_M)` or `(BATCH_BLOCK, BLOCK_N)`) before expanding dimensions, and hoisting completely loop-invariant exponentials out of the inner loop entirely, reduces redundant MUFU operations significantly without changing behavior.
**Action:** Always check if element-wise functions like `jnp.exp` can be applied to lower-dimensional tensors before broadcasting `[:, None, :]` or `[:, :, None]`, and hoist loop-invariant computations out of inner loop `jax.lax.fori_loop` bodies.
